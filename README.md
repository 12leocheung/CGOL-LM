# CGOL-LM

A small-scale experiment to see if a hybrid architecture of **Conway's Game of Life** and **Hyper-Dimensional Computing (HDC)** can be used to make a language model.

Instead of gradient descent and matrix multiplication, CGOL-LM represents each word as a high-dimensional bipolar vector and places it on a 2D grid. Words that share semantic context are pulled toward each other over successive "generations," turning the grid itself into a spatial map of meaning. Text is then generated by walking across that grid, guided by both the corpus's word-transition statistics and the vectors' semantic similarity.

## How it works

**1. Encoding words as hypervectors (HDC)**
Every unique word in the training corpus is assigned a random bipolar vector of dimension `d = 10000` (entries of `-1` or `+1`). Three HDC primitives are used to build meaning from context:

- `shift(vec, offset)` — a positional rotation, used to encode *where* a context word sits relative to the target word (via `np.roll`)
- `bind(v1, v2)` — element-wise multiplication, used to combine two vectors
- `bundle(vectors)` — element-wise majority sign across a set of vectors, used to superimpose several vectors into one

For each word in each training sentence, the vectors of its neighboring words (within a window of 2 on each side) are shifted by their relative offset and bundled together to form that occurrence's context vector. All of a word's context vectors across the corpus are then bundled into a single **semantic vector**, giving every word a representation shaped by how it's actually used in the data.

**2. Grouping words**
Each word's semantic vector is compared (via normalized dot-product similarity) against a running set of group vectors. A word joins the most similar existing group if the similarity clears a threshold (`similarity_threshold = 0.04`), or starts a new group otherwise. This produces clusters of semantically related words.

**3. Placing words on a grid (Conway's Game of Life)**
Every word is placed at a random position on a 2D grid sized to just fit the vocabulary. Over a number of epochs, each word "moves" one cell at a time toward the centroid of the other members of its semantic group — but only if none of its known next-words (from the training bigrams) are already sitting in an adjacent cell. This is the Game-of-Life-inspired part: local neighborhood state determines whether a cell updates on each generation, and the grid gradually self-organizes so that semantically related words drift into the same neighborhood.

**4. Generating text**
Generation starts from a seed phrase and repeatedly picks a next word by:
1. Looking for words that followed the current word anywhere in the training sentences.
2. If none are found, falling back to the current word's 8 neighboring cells on the trained grid.
3. Scoring the candidates by HDC cosine-style similarity to the current word's semantic vector, preferring candidates not already used in a recent bigram or the last few words (to reduce repetition).
4. Randomly sampling from the top 3 scored candidates.

The result is a lightweight, non-gradient-based language model where "training" is really a spatial self-organization process, and "inference" is a walk across the resulting map.

## Repository contents

| File | Description |
|---|---|
| `CGOL_train.py` | Builds word vectors and semantic vectors via HDC, groups words by similarity, initializes the grid, runs the Game-of-Life-style training loop, and pickles the result to `cgol_model.pkl`. |
| `CGOL_run.py` | Loads `cgol_model.pkl` and generates text interactively from a seed phrase typed at the prompt. |
| `small_dataset.txt` | 17 sentences / 81 unique tokens. Good for quickly sanity-checking the pipeline. |
| `medium_dataset.txt` | 8,585 sentences / 1,245 unique tokens. |
| `large_dataset.txt` | 28,821 sentences / 2,265 unique tokens. |

Each dataset is a JSON array of sentences, where each sentence is itself a JSON array of word tokens, e.g.:

```json
[
    ["An", "entity", "can", "exist", "independently", "of", "other", "things."],
    ["The", "physical", "world", "can", "be", "observed", "through", "our", "senses."]
]
```

## Usage

**1. Train a model**

By default, `CGOL_train.py` reads from `medium_dataset.txt`. Edit the `file_path` variable at the top of the script to point at `small_dataset.txt` or `large_dataset.txt` instead (or your own dataset in the same JSON format):

```python
file_path = r"medium_dataset.txt"
```

Then run:

```bash
python CGOL_train.py
```

This will:
- Build word and semantic vectors,
- Group words by semantic similarity,
- Run the grid-based training loop for `epochs=25` (adjustable in the `train(...)` call at the bottom of the script),
- Print per-epoch progress (moves made, adjacency-blocked words),
- Save the trained state to `cgol_model.pkl`,
- Print the final grid layout.

**2. Generate text**

```bash
python CGOL_run.py
```

This loads `cgol_model.pkl`, prints the trained grid, and then prompts you for a seed phrase:

```
Enter a seed word to generate a sentence (or 'exit' to quit): The Sun
Generated Sequence: The Sun is a main_sequence star.
```

Type `exit` to quit. Note that only words present in the training vocabulary can be used as seeds.

## Key parameters

Both scripts share a few constants worth tuning:

| Parameter | Location | Default | Effect |
|---|---|---|---|
| `d` | both scripts | `10000` | Hypervector dimensionality. Higher dimensions reduce random collisions between unrelated vectors but cost more memory/compute. |
| `window` | `CGOL_train.py` | `2` | Context window size (words on each side) used to build semantic vectors. |
| `similarity_threshold` | `CGOL_train.py` | `0.04` | Minimum similarity for a word to join an existing semantic group rather than start a new one. Lower values produce fewer, larger groups. |
| `epochs` | `CGOL_train.py` (`train(...)` call) | `25` | Number of Game-of-Life-style movement generations run on the grid. |
| `max_length` | `CGOL_run.py` (`generate_sentence(...)` call) | `15` | Maximum number of words to generate per sentence. |

## Current status

This is an early-stage, working prototype. It demonstrates the core loop end-to-end — encode, group, self-organize on a grid, and generate — on datasets ranging from a handful of sentences to tens of thousands. It's a proof of concept rather than a production language model: there's no beam search, no perplexity evaluation, and generation quality is highly dependent on dataset size and the tuning of `similarity_threshold` and `epochs`.

## Ideas for future work

- Replace random grid placement with a smarter initialization (e.g. seeded by semantic similarity) to speed up convergence.
- Explore alternative Game-of-Life-style survival/movement rules beyond centroid-seeking.
- Add quantitative evaluation (e.g. perplexity, coherence scoring) to compare against a baseline n-gram or small transformer model.
- Support larger vocabularies and streaming/batch training for datasets beyond `large_dataset.txt`.
